# LinxSci OpenAPI v2

[简体中文](api.zh-CN.md)

Use the service root `https://linxsci.com` with the `/openapi/v2` prefix. All endpoints require a LinxSci API key. JSON business fields, pagination and task status fields follow the selected endpoint's API contract.

## Authentication and tracing

| Header | Required | Purpose |
| --- | --- | --- |
| `Authorization: Bearer <LinxSci OpenAPI Key>` | Yes | Client authentication |
| `X-Request-ID` | No | Provider/proxy trace ID; the SDK generates one when omitted |
| `X-ANYTHINGRIGHT-REQ-ID` | No | Framework trace ID, returned as `extra.request-id` on framework errors; generated by the service when omitted |
| `X-MinerU-API-Key` | When required | Additional key for PDF parsing endpoints |

Configure the client key using local setup or `LINXSCI_OPENAPI_KEY`. The service handles its own provider authentication; client applications only supply the headers above as needed.

Paper IDs support `local:`, `arxiv:`, `openalex:`, `s2:`, and `doi:` prefixes. Encode each dynamic path segment, including slashes in DOIs, for example `doi:10.1000%2Fexample`. Convenience SDK/CLI methods accept raw IDs and encode them. Generic requests require pre-encoded paths. Prepare POST JSON according to the endpoint contract; `{}` is not a universally valid request. PDF upload uses the multipart `file` field; file limits and additional fields depend on the service.

## Usage and limits

Each request has an expected call quantity of 1. A provider 2xx response corresponds to an actual quantity of 1; other statuses or connection failures correspond to 0. Reserved credits are released after the service confirms accounting completion. A failed HTTP response alone does not establish that credits have been released. Daily limits and endpoint availability are enforced by the service; inspect `usage` and the error codes below when needed.

## Responses and errors

Successful provider responses retain their status, body and relevant headers (`Content-Type`, `X-Request-ID`, `Retry-After`, and `Cache-Control`). Provider business errors such as `validation_error` and `asset_unavailable` keep their own response schemas. The SDK preserves raw response bytes. CLI presentation, field selection and file output are described in the [command guide](cli.md#compact-output-and-explicit-response-views).

Framework authentication, service configuration, usage and connection errors use:

```json
{
  "code": -1,
  "data": {},
  "error": {
    "code": -3900,
    "msg": "This endpoint is not enabled. Contact the service administrator."
  },
  "extra": {"request-id": "example-request-id", "cost": 0.01}
}
```

This example has HTTP status 503. `extra.cost` is elapsed time in seconds, not a monetary charge. `extra.request-id` comes from `X-ANYTHINGRIGHT-REQ-ID` or is generated by the service.

| HTTP | `error.code` | Meaning and action |
| --- | --- | --- |
| 401 | `-401` | Missing or invalid client key; check Authorization or run setup |
| 404 | `-404` | Unsupported method or path; check the route table |
| 503 | `-3900` | Endpoint not enabled; contact the service administrator |
| 429 | `-3901` | Daily limit reached; wait for reset or contact the administrator |
| 503 | `-3902` | Provider connection settings are missing; contact the administrator |
| 502 | `-3903` | Provider connection/transport failed; check service connectivity before retrying |
| 502 | `-3904` | Request preparation failed before forwarding; contact the administrator |
| 502 | `-3905` | Provider returned but accounting completion is unconfirmed; check execution and billing before retrying |

Preserve both trace IDs and any `Retry-After` value for troubleshooting. Do not automatically repeat uploads or task creation after an uncertain result. In particular, `-3905` does not mean the operation failed to execute, and `Retry-After` does not resolve that uncertainty.

## Manual clients

In Postman or another HTTP client, configure the service root and bearer key, then use the routes above. For POST requests, prepare the documented endpoint-specific JSON. For `/openapi/v2/pdf/parse/upload`, select the local PDF in the multipart `file` field.
